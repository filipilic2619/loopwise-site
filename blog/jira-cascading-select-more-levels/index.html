Jira cascading select with more than two levels

Jira's built-in Select List (cascading) field has exactly two levels: a parent and a child. That covers Country › City, but not Region › Country › City, or Product › Component › Area. Here are your options.

Option 1: Two-level cascading select plus a second field

Use the built-in cascading field for the first two levels and a separate select list for the third. It is free, but the third list cannot depend on the first two: people see every option, and invalid combinations get through.

Option 2: Combine levels into one option

Put two levels into one option, such as "Europe – Germany" › "Berlin". It works for small trees, but the option list grows fast and reports become harder to read.

Option 3: A multi-level cascading select field

Cascading Select for Jira adds a field type with up to six dependent levels. Each dropdown only offers the options under the one chosen above it.

  1. In Jira settings → Issues → Custom fields, create a field of type Multi-level select (Loopwise) and add it to your screens.
  2. In the field's configuration, type or paste the whole option tree as an indented list. Indent to nest.
Europe
  Germany
    Berlin
    Munich
  France
    Paris
North America
  USA
    New York
  1. Optionally name the levels (Region, Country, City) and require a choice down to the last level.

The value is stored as plain text, such as Europe › Germany › Berlin, so it shows up cleanly in exports, filters and dashboards and can be searched by exact value. It works on create, edit and transition screens in company-managed projects.

Which one should you use?

  • Two levels are enough: use the built-in field.
  • Three or more levels, and wrong combinations matter (routing, reporting, SLAs): use a multi-level field.
