How to create recurring issues in Jira Cloud

Jira Cloud has no "repeat this issue" button. If your team has a weekly report, a monthly access review or a daily standup ticket, someone has to remember to create it, or you set it up once with one of the three options below.

Option 1: Jira Automation with a scheduled trigger

Jira's built-in automation can create an issue on a schedule.

  1. Go to Project settings → Automation and choose Create rule.
  2. Pick the Scheduled trigger and set the interval, for example every Monday at 09:00. For anything more specific, use a cron expression.
  3. Add the action Create issue and fill in the summary, issue type and assignee. Smart values such as {{now.format("yyyy-MM-dd")}} add the date to the title.
  4. Turn the rule on.

Good for: one or two simple schedules in a single project.

Watch out for:

  • Every run counts toward your plan's monthly automation limit.
  • Schedules beyond "every N days" need cron syntax.
  • The new issue is not added to the active sprint unless you add more steps.
  • With many rules it is hard to see which schedule creates what.

Option 2: Clone a template issue

Keep one "template" issue per routine task and clone it when needed: manually, or with an automation rule that clones it on a schedule. Cloning copies the description, labels and sub-tasks.

Good for: routine work with a long checklist of sub-tasks.

Watch out for: template issues show up in searches and boards unless you hide them, and you still need a schedule (option 1) or a person to do the cloning.

Option 3: A recurring-issues app

A dedicated app keeps every schedule in one list and handles the details the other options leave to you.

Recurring Issues for Jira is ours:

  • Plain-language schedules: every weekday, every second Monday, the last day of the month. A preview shows the next five runs, so no cron is needed.
  • Time zone per rule: 09:00 stays 09:00 after daylight saving changes.
  • Sprint-aware: new issues can go straight into the active sprint, and the previous unfinished copy can be closed automatically.
  • Placeholders such as {{date}}, {{weekday}} and {{week}} in titles and descriptions.

It runs entirely on Atlassian and does not use your automation limit.

Which one should you use?

  • One simple weekly issue: Jira Automation is enough.
  • A long checklist that repeats: clone a template issue, or use Issue Templates.
  • Many schedules, several teams or time zones, sprint-based work: a recurring-issues app saves time and avoids missed tickets.
